# 完整執行順序 —— 從零開始跑一遍

所有指令都在 **repo 根目錄** (`sclaudecode/`) 執行。

```bash
export PYTHONPATH=src        # Windows PowerShell: $env:PYTHONPATH="src"
```

---

## ① 錄一份資料

```bash
python -m hardware.record_session --port COM9 --subject gary
```

→ `multi_gary_YYYYMMDD_HH-MM-SS.{csv,_cues.csv,_meta.json}`

⚠️ 電極位置照 `00_config/README.md` 的表（ch1 背闊、ch2 二頭、ch3 三頭、
ch4 三角肌前束、ch5 曲腕、ch6 食指、ch7 拇指）。
⚠️ 維持姿勢時手臂必須**懸空**。

---

## ② ★ 品質檢查（錄完立刻跑，先於一切）

```bash
python -m semg.v2.plot_signal 剛錄的.csv --out results/signal_qc
```

七個通道都要 **OK**，特別是 **60 Hz 都 < 10%**。
不合格 → **重貼電極重錄**，不要繼續往下。

**建議流程**：貼好電極 → 先錄 30 秒 → 跑這個 → 過了再錄那 9 分鐘。
否則錄完 9 分鐘才發現不能用。

接著檢查動作有沒有做錯：

```bash
python -m semg.v2.audit_trials 剛錄的.csv
```

## ③ 把這份加進錄音清單

編輯 `configs/recordings_v5.txt`，加一行 stem（不含副檔名）。
這個檔是**單一事實來源** —— 所有訓練與評估都讀它。

## ④ ★ 交叉驗證（產生「數字」）

```bash
# 留一份錄音（與舊結果對比用）
python -m semg.v2.leave_one_recording_out \
    --data-root V5moving/data --include configs/recordings_v5.txt \
    --arch split --no-hampel --jobs 4 \
    --out results/loro_v5_nohampel

# ★ 留一貼片場次（要報的數字）
python -m semg.v2.leave_one_recording_out \
    --data-root V5moving/data --include configs/recordings_v5.txt \
    --arch split --no-hampel --scheme session --jobs 3 \
    --out results/loso_session_v5_nohampel
```

輸出：`summary.csv`（逐折數字）、`*_model.pt`（每折的模型）、
`*_predictions.csv`、`*_overview.png`。

**耗時**（4 核心 CPU + 2080 SUPER）：
資料集建置 124 s（no-Hampel）或 341 s（開 Hampel），
之後每折約 60 s，`--jobs 4` 平行。

⚠️ 換清單或換 Hampel 設定時要加 `--force` 重建快取。

## ⑤ 訓練部署模型

```bash
python -m semg.v2.train_final \
    --data-root V5moving/data --include configs/recordings_v5.txt \
    --arch split --no-hampel \
    --cache results/loro_v5_nohampel/dataset.npz \
    --out results/final_v5/models/final_v5_split.pt
```

→ `.pt` + `_scripted.pt`（TorchScript）+ `.json`

⚠️ 這個模型**沒有自己的準確率**。要報的數字引用 ④ 的
留一貼片場次平均，**不要**引用訓練集準確率。

# 各階段耗時速查

| 階段 | 耗時 |
|---|---|
| ① 錄一份 | 9 分 10 秒 + 貼電極 |
| ② 品質檢查 | ~30 秒/份 |
| ④ LORO（7 折，no-Hampel，jobs 4） | ~8 分 |
| ④ 留一場次（3 折） | ~10 分 |
| ⑤ 訓練最終模型（用快取） | ~2 分 |
| ⑥ 離線重播一份 | ~70 秒 |

⚠️ 瓶頸是**串流重播**（CPU 單執行緒 scipy），不是 GPU 訓練
（11,625~17,530 參數，60 秒/折）。
`--jobs` 平行化與關掉 Hampel 是唯二有效的加速手段。

# 常見錯誤

| 症狀 | 原因 | 解法 |
|---|---|---|
| 載入模型時報 `feat_version` 不符 | 模型是舊特徵定義訓練的 | 重訓，或用對應版本的程式 |
| 換清單後數字沒變 | 用到舊的 `dataset.npz` 快取 | 加 `--force` |
| 雙模型比較報 Hampel 不一致 | 兩個模型的 `use_hampel` 不同 | 換成設定相同的兩個模型 |
| `--conf` 調了沒反應 | ★ 信心值飽和在 1.00 | 改用 `--bias` |
| shoulder 完全不觸發 | 校準段不夠安靜，尺度被高估 | 校準時保持完全靜止 |
| 準確率在不同次 run 差很多 | ★ 電極貼附品質 | 跑 `plot_signal` 確認 60Hz |
