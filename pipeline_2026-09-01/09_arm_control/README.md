## 硬體與映射

| 項目 | 值 |
|---|---|
| 手臂 | uFactory Lite 6，IP `192.168.1.166` |
| Home 姿態 | J1..J6 = `[90, −90, 180, 0, 0, 0]` |
| **elbow → J3** | `ELBOW_FLEX_ANGLE = 90.0`（屈肘至垂直上臂） |
| **shoulder → J2** | `SHOULDER_FLEX_ANGLE = 0.0`（平舉水平） |
| **hand → 夾爪 + J6** | 夾爪 toggle；J6 jog `JOG_RATE_DEG_S = 45 °/s` |

### elbow/shoulder 是**位置鏡像**，hand 是**狀態切換**

這個差別決定了兩者需要完全不同的去彈跳策略：

- J2/J3：狀態一變就是 **90° 大擺動** → 誤判代價很高
- 夾爪 / J6：要的是**即時反應**，「放手即停」不能拿去換

## ★ 三道去彈跳閘（debounce.py）

每個自由度各自維護一個 `DofDebouncer`，**各自獨立**跑自己的狀態機。

⚠️ 為什麼不對整個組合投票：那會讓「食指穩定彎曲但肩膀在抖」
連食指的輸出一起被否決。逐 DOF 投票才是多輸出架構該有的行為。

| 閘 | 參數 | 擋什麼 |
|---|---|---|
| ① 信心門檻 | `P_MIN = {hand: 0.80, elbow: 0.75, shoulder: 0.75}` | 低信心幀（視為「無意見」，不推進也不重置投票） |
| ② N-of-M 多數決 | `VOTE_M = 6`, `VOTE_N = 4`（300 ms 視窗） | 抖動 |
| ③ 不反應期 | `REFRACTORY = {hand: 0.60, elbow/shoulder: 0.40}` | 同一個動作被雜訊拆成兩次觸發 |

### 兩個容易忽略的設計細節

**① 投票視窗有【時間】上限**（`VOTE_WINDOW_SEC = 0.50 s`）

閘①會跳過低信心幀，所以「最近 6 幀」不等於「最近 6 × 0.05 秒」。
疲勞或過渡期會產生連續低信心幀，若不加時間上限，緩衝區的 6 幀
可能橫跨數秒 —— **幾秒前的舊姿勢會在此刻湊滿多數決並觸發轉態**
（例：使用者已放鬆，夾爪卻因 3 秒前的舊 pinch 幀而閉合）。

**② 進入 rest（狀態 0）不受 refractory 限制**

refractory 的目的是防止「單一動作被拆成兩次觸發」，這只在進入**動作**狀態時有意義。
套用在「回到 rest」上會製造兩個反效果：

1. index/thumb 放鬆後，J6 會多轉 refractory 那段時間才停 ——
   **使用者回報「一次轉到底」的根因**，jog 在延遲裡持續累積，嚴重時撞軟限位
2. 「放開再夾一次」的第二次 pinch 上升緣若卡在前一次的 refractory 視窗內，
   會被靜默吃掉

## ★ 第四道閘：MIRROR_MIN_HOLD_SEC（2026-08-19 加入）

### 問題

實測有 **0.25–0.45 s 的短脈衝**（模型短暫誤判成 flex 又跳回 rest），
每一個都讓手臂往 90° 外衝一段再被拉回來 —— 這是抽動的成因。

### ⚠️ 為什麼既有三道閘都擋不住

| 閘 | 為什麼擋不住 |
|---|---|
| `P_MIN` | 這些脈衝的信心值是 **0.78~1.00**，本來就高 |
| `VOTE_M/N` | 實測換成 6/4 兩層投票，反向比例 77%/79%，與單層 74%/79% 幾乎相同 |
| `REFRACTORY` | 它對「轉回 rest」是**刻意豁免**的（上面說的 hand 需求） |

★ 這裡獨立驗證了 `08_inference/README.md` 提到的**信心值飽和**現象。

### 修法

`MIRROR_MIN_HOLD_SEC = 0.5` —— **只作用在 elbow/shoulder**：
新狀態要連續維持 0.5 s，才允許更新 J2/J3 的目標角。
hand（夾爪 toggle 與 J6 jog）**完全不受影響**。

### 效果（實測）

| 指標 | 之前 | 之後 |
|---|---|---|
| J3 未走完就反向 | 47% | **12%** |
| J2 未走完就反向 | 56% | **15%** |
| 最短脈衝 | 0.25–0.30 s | 0.70–0.80 s |

**代價：elbow/shoulder 反應延遲 +0.5 s。**（見 `延遲分析.md`）

## 目標角的推進方式

⚠️ 目標角**不是**一步跳到位，是按「實際經過時間 × 速率」**連續推進**：

```python
step = MIRROR_RATE_DEG_S * min(dt, CMD_PERIOD * 3)
```

`MIRROR_RATE_DEG_S = 60 °/s` → 90° 行程需 **1.5 s**。

這與最小維持閘是**互補**的：

```
最小維持閘  擋「根本不該動」的短脈衝（0.25~0.45s 的誤判）
逐步推進    讓「該動但中途反悔」的情況平滑折返，而不是猛然打斷
```

### ⚠️ 加速度刻意保持低值

`JOINT_ACC = 200 °/s²`（出廠上限 1145 的 17%）。

教訓來自 `JOG_ACC = 1100` 的失敗：mode 6 下高加速度不會讓動作更順，
只會變成**每個指令週期一次的力矩衝擊**，激振整條手臂。
想讓 J2/J3 更快請調 `MIRROR_RATE_DEG_S`，不是加速度。
