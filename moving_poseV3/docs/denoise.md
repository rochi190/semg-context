# 環境雜訊抑制：我選了什麼、為什麼、以及測出來的結果

> 2026-09-12。moving_poseV3 相對 V2 的主要新增。

---

## 1. 問題是什麼

**訓練資料與部署環境的雜訊條件不同。**

- 訓練用的 9 份錄音錄在**安靜**的地方
- 機械手臂放在**實驗室**（運轉中的電器多、市電干擾大）

所以離線量到的所有準確率**都不保證能轉移到實機**。這也解釋了先前
「離線量測與實機觀察對不上」的現象（見 `results/subject_compare/README.md`）。

### 兩條可能的路

| 做法 | 優點 | 缺點 |
|---|---|---|
| A. **在實驗室重錄訓練資料** | 訓練與部署條件一致，最乾淨 | 要重錄所有人；而且雜訊會隨當天開了哪些電器變動 |
| B. **部署時降噪**，把吵環境映射回乾淨環境 | 不用重錄；對雜訊變動有適應性 | 降噪本身會失真，可能傷到訊號 |

**本次做 B**（A 仍然建議做，見 §7）。

★ **B 的成立條件**：降噪演算法必須在**乾淨訊號上接近恆等**。
　 否則模型（用乾淨資料訓練）在乾淨環境反而變差 —— 得不償失。

---

## 2. 驗證方法：兩個必要測試

每個演算法都必須同時通過：

```
① 乾淨訊號中性測試
   在乾淨錄音上開啟該演算法，準確率不能下降。
   → 這是「不能讓事情變糟」的底線。

② 加噪可回復測試
   在乾淨錄音上注入真實的實驗室型雜訊，開啟該演算法要把準確率救回來。
   → 這是「真的有用」的證據。
```

**只過 ② 不過 ① 的演算法不能用。**

### 雜訊模型

用**真實汙染**而非合成弦波：取全套最髒那份錄音
（`multi_gary_20260821_22-03-40`，ch1 的 60Hz 佔 81.9%）的**休息段**，
帶通到 20–450 Hz，逐通道歸一化成單位 RMS，再按 5 µV / 15 µV 注入。

⚠️ 為什麼不用合成 60Hz 弦波：那會讓 comb/lms 看起來好得不真實 ——
　 真實干擾有時變的振幅、相位、諧波結構，合成訊號沒有。

⚠️ 為什麼要先帶通：第一版直接用未濾波的休息段，RMS 是 500–2280 µV
　 （低頻漂移主導），加進去會讓訊號變成純雜訊，什麼都測不出來。
　 管線本來就會濾掉 <20Hz，所以只有**通帶內**的雜訊才是威脅。

## 3. 候選演算法與選擇邏輯

### 3.1 `comb` — 諧波梳狀陷波

**對付**：120/180/240/300/360/420 Hz 的市電諧波。

**為什麼需要**：現有的陷波器只殺 60 Hz **基頻**。諧波全部落在
20–450 Hz 通帶內，原封不動進到特徵。

**直接證據**：

| 量測 | 與 LORO 準確率的相關 |
|---|---|
| 陷波**前**的 60Hz 佔比 | r = −0.942 (p = 0.001) |
| 陷波**後**的 60Hz 殘餘 | r = −0.166 (p = 0.72) ← **不相關** |
| **諧波 120–420 Hz** | **r = −0.849 (p = 0.016)** |

基頻已經被處理掉了 —— **還在傷害準確率的是諧波**。

**代價**：6 個凹陷 × (f/Q) ≈ 12 Hz，佔 430 Hz 通帶的 2.8%。
肌電在那些頻率有能量，所以這不是免費的。

### ★ 「我已經有 60Hz 陷波器了，還不夠嗎？」

這是對的問題，而且**一半的答案是「夠了」**：陷波後的 60Hz 殘餘與準確率
**不相關**（r = −0.166, p = 0.72）。基頻那道確實有效。

不夠的是**諧波**。實測 `multi_gary_20260821_22-03-40` 的 ch1：

#### 現行陷波器（2階 Q=30）的實際頻率響應

| 頻率 | 衰減 |
|---|---|
| 59.0 Hz | −2.97 dB |
| 59.5 Hz | −6.96 dB |
| 59.9 Hz | −20.04 dB |
| **60.0 Hz** | **−239 dB** |
| 60.1 Hz | −20.05 dB |
| **120 / 180 / 240 / 300 / 360 / 420 Hz** | **−0.00 dB** |

兩件事：

**① 凹陷很深但極窄。** 市電不是剛好 60.000 Hz，漂到 59.9 就只剩 −20 dB。
實測整份錄音的有效衰減是 **−23.6 dB**，與「市電不在正中心」一致，
不是頻譜圖上看起來的 −239 dB。

**② 諧波完全沒被碰到**（−0.00 dB）。單一個 2 階區段只在 60Hz 有凹陷。

#### 絕對功率（ch1，µV²）

| 階段 | 通帶總功率 | 60Hz | **諧波 120–420** | 其餘（肌電） |
|---|---|---|---|---|
| 只帶通 | 1736.6 | 1421.6 | 143.5 | 171.6 |
| **陷波+帶通（現行）** | 335.0 | **6.1** | **144.7** | 184.2 |
| ＋`comb` | 186.5 | 6.1 | **0.5** | 179.9 |

陷波器把 60Hz 從 1421.6 打到 6.1（**有效**），但諧波 143.5 → 144.7（**沒動**）。

⚠️ **關鍵**：陷波後，諧波（144.7）與真正的肌電（184.2）是**同一個量級**——
在這條通道上，剩下的訊號有 **43%** 是市電諧波。
（諧波佔比從 8.26% 升到 43.20% **不是**陷波器製造了諧波，
　是分母掉了 80%。但這正是重點 —— 特徵吃的是**形狀**不是絕對值。）

#### 對特徵的實際影響（同一段訊號，ch1）

| 特徵 | 現行 | ＋comb | 變化 |
|---|---|---|---|
| `mnf`（平均頻率） | 70.60 | 43.95 | **37.7%** |
| `bandwidth` | 80.78 | 48.44 | **40.0%** |
| `zc`（過零率） | 123.0 | 96.0 | **22.0%** |
| `mfcc1` | −34.81 | −32.56 | 6.5% |
| `mdf`（中位頻率） | 31.25 | 31.25 | 0.0% |
| `pkf`（峰值頻率） | 27.34 | 27.34 | 0.0% |

120 維特徵裡有 4 維是頻域矩（`mnf`/`mdf`/`pkf`/`bandwidth`），
其中 `mnf` 與 `bandwidth` 是**能量加權**的 → 對線譜極敏感，被推了 38–40%。
`mdf`/`pkf` 是中位數/峰值，對線譜穩健，完全沒動。

★ 也就是說：模型在乾淨資料上學到「這種訊號的 mnf ≈ 44」，
　 汙染通道給它 70.6 —— 那是**訓練分布外**的輸入。

#### `comb` 之後還剩什麼

| 殘留 | 佔 comb 後通帶功率 |
|---|---|
| 60 的整數諧波（120–420） | **0.27%** |
| 60 的**半整數**倍（150/210/270/330/390） | 1.16% |

半整數倍那組可能來自切換式電源的倍週期。`comb` 沒針對它們，
但 1.16% 低於值得再挖 5 個凹陷的門檻（每個凹陷要付 2 Hz 通帶）。
**已知、已量、刻意不處理。**

視覺版見 `fig_notch_vs_comb.png`。

### 3.2 `lms` — 自適應市電消除

**對付**：會漂移的市電基頻與諧波。

**為什麼比陷波器好**：陷波器在 60Hz 挖一個**永久的洞** ——
不管當下有沒有干擾，肌電在那個頻率的成分也一起被挖掉。

LMS 只減去「與參考弦波同調」的成分：

```
ŷ[n] = w_c·cos(2πf n/fs) + w_s·sin(2πf n/fs)
e[n] = x[n] − ŷ[n]
w   ← w + μ·e[n]·r[n]
```

干擾大時權重長大、干擾消失時衰減回 0 → **不留下頻譜洞**，
而且會追蹤市電的振幅與相位漂移（市電不是剛好 60.000 Hz）。

**參數**：μ = 2e-3（時間常數 1/(μ·fs) ≈ 0.25 s，遠慢於肌電變化）。
追 60/120/180/240 Hz 四個頻率。

⚠️ μ 太大會讓權重去擬合肌電的隨機成分 = 把訊號也減掉。

### 3.3 `car` — 分組共同平均參考

**對付**：共模環境場（所有電極收到同一個干擾）。

**原理**：環境電磁場對所有電極的耦合量幾乎相同，而肌電是**局部**的。
減掉跨通道的共同成分就減掉干擾、保留肌電。

**★ 為什麼是「分組」不是全 7 通道**：這是**架構一致性**要求。
`SplitMultiHead` 的整個設計目的就是讓近端與遠端**完全不互通**
（留一組合測試 5.0% → 85.4%）。做全陣列 CAR 會把近端活動減進遠端通道 ——
**等於把特地切斷的耦合又接回去**。

**⚠️ 一個已修的實作錯誤**：第一版用 median 估共模（想說比較穩健）。
但遠端只有 3 個通道，**3 個數的中位數就是其中一個** ——
`sub − median(sub)` 會把「當下是中位的那條通道」**逐樣本歸零**。
那不是穩健，是把訊號毀掉。改用 mean。

### 3.4 `hampel` — 突波抑制

**對付**：繼電器、馬達切換產生的脈衝干擾。

現有機制，這次只是把它變成可以在命令列開關。
⚠️ 它佔每視窗計算的 77%（14.1 ms），而在**乾淨**資料上
3 種子 × 7 折的消融顯示 p = 0.926（分不出差異）——
所以平常是關的。吵環境下才可能有價值。

### 3.5 `wavelet` — 小波軟閾值（實驗性）

**對付**：寬頻雜訊。文獻上 EMG 去噪常引用。

**⚠️ 我對它有三個先驗保留**：
1. universal threshold 假設雜訊是**高斯白雜訊**，
   但市電干擾是窄頻確定性訊號 —— 小波對它的效率不如陷波/LMS
2. 計算成本最高
3. 軟閾值會壓低**所有**小幅訊號，包含 chou 那種本來就很小的肌電

實作出來是為了讓你能比較，不是因為我推薦它。

### 3.6 `nf` — 雜訊底噪補償（不是濾波器）

**對付**：吵環境讓校準尺度 α 被墊高的問題。

**機制**：α 是從休息段估的，吵環境下休息段**包含環境雜訊** →
α 被墊高 → 所有 `*_rel` 振幅特徵被壓扁 → 該自由度看起來永遠接近 rest。
（先前使用者回報「shoulder 完全不觸發」就是這個機制。）

**做法**：從 350–450 Hz（幾乎沒有肌電）估寬頻雜訊底，在**功率域**扣掉：

```
α_corrected = sqrt( max(α² − σ_noise², (0.3α)²) )
```

下限 0.3α 是防呆 —— 估錯時不能讓 α 掉到 0 導致特徵爆炸。

⚠️ 這個假設在**窄頻**干擾下不成立（線狀譜不是白的），
所以 `nf` 要跟 `comb`/`lms` **一起用**：先殺線狀譜，剩下的才適合這個模型。

## 3.7 實測結果

基準模型 `final_v5_split`（用乾淨資料訓練）。**三位受試者**：gary `17-23-12`、
neil `21-54-56`、chou。

### 第一階段：乾淨訊號中性（gary，全 6 個候選）

| 演算法 | 乾淨全對 | Δ | 判定 |
|---|---|---|---|
| （關閉） | 99.5% | — | 基準 |
| `lms` | **99.5%** | **0.0** | ✅ |
| `nf` | 99.2% | −0.3 | ✅ |
| `comb` | 98.8% | −0.7 | ✅ |
| `car` | 84.5% | **−15.0** | ❌ 淘汰 |
| `wavelet` | 65.0% | **−34.5** | ❌ 淘汰 |
| `hampel` | 63.9% | **−35.6** | ❌ 淘汰 |

（未通過①的三個沒有再測②——不管加噪表現多好都不能用。）

### 第二階段：三位受試者 × 通過的組合

Δ 相對「關閉」，正數越大越好：

| 演算法 | 乾淨 Δ（gary/neil/chou） | 平均 | 加噪 15µV Δ | 平均 |
|---|---|---|---|---|
| `comb` | −0.7 / −0.5 / −0.7 | −0.63 | +5.8 / +7.9 / +3.9 | +5.87 |
| `lms` | **0.0 / −0.3 / −0.1** | **−0.13** | +8.0 / +5.5 / −0.7 | +4.27 |
| `nf` | −0.3 / −0.6 / −1.2 | −0.70 | +13.6 / +4.5 / +0.0 | +6.03 |
| `comb+lms` | −2.3 / −0.7 / −0.5 | −1.17 | +5.9 / +7.9 / +2.3 | +5.37 |
| `lms+nf` | −0.4 / −1.3 / −1.1 | −0.93 | +16.0 / +8.4 / +0.3 | +8.23 |
| **`comb+lms+nf`** | −0.9 / −1.3 / −1.0 | −1.07 | **+17.2 / +10.0 / +1.6** | **+9.60** |

**→ 建議 `--comb --lms --nf`**：三個人的加噪回復都是最高，
乾淨訊號只多付 0.14 pp（相對次佳的 `lms+nf`）。

### ⚠️ 兩個被三人資料修正的說法

我先前只看 gary 一人時寫過兩句話，三人資料都推翻了：

**① 「`nf` 是單項最強」—— 只在 gary 身上成立。**
gary +13.6、neil 只有 +4.5、chou +0.0。三人平均 +6.03，
與 `comb` 的 +5.87 幾乎打平。gary 那個 +13.6 是個案不是通則。

**② 「建議 `lms+nf`」—— 應該是 `comb+lms+nf`。**
加了 `comb` 之後三個人**都**更好（+1.2 / +1.6 / +1.3），
而乾淨訊號的額外代價只有 0.14 pp。

★ 這正是為什麼測試要**跨受試者**：單一受試者的最佳解可能只是那個人的特性。

### ⚠️ 降噪救不了 chou

| chou | 乾淨 | 加噪 15µV |
|---|---|---|
| 關閉 | 69.5% | 51.3% |
| 最好的降噪 | 69.4%（`lms`） | 55.2%（`comb`） |

他的手部訊號本來就只有 4.7 µV（別人 28–59 µV），
加 15 µV 雜訊等於訊號被埋掉 —— 沒有演算法救得回來。
**他需要的是重新調整電極位置，不是降噪。**

### 三個淘汰的，原因各不相同

**`hampel` −35.6 pp：這不是 Hampel 的問題，是我分類錯了。**
模型是 `use_hampel=False` 訓練的，推論時打開 = **訓練/推論前處理不一致**。
要用它必須**重新訓練**，不是切換旗標。
本專案把 `use_hampel` 寫進 bundle 就是為了防這種誤用 ——
結果我自己又把它當成可切換的降噪選項。

**`car` −15.0 pp：這是真的失敗。**
遠端只有 3 個通道、近端 4 個。減掉組內平均會把真實肌電也減掉
（elbow 99.6% → 75.4%）。CAR 需要「訊號相對陣列是局部的」，
通道數太少時這個前提不成立。

**`wavelet` −34.5 pp：軟閾值壓掉所有小幅訊號**，
包含 chou 那種本來就很小的肌電。

### ★ 為什麼 `nf` 在 gary 身上特別有效

因為雜訊最主要的傷害**不是波形變醜**，而是**墊高校準尺度 α**：

```
rms_rel = RMS_go / α
吵環境下 α 變大 → 所有相對振幅特徵被壓扁 → 看起來永遠接近 rest
```

gary 的 hand 從 81.8% → **99.3%**。`comb`/`lms` 是在「把雜訊從波形移除」，
`nf` 是在「把雜訊從尺度估計移除」—— 後者更直接命中傷害機制。

⚠️ **但這個效果因人而異很大**：neil +4.5、chou +0.0。
　 取決於該受試者的休息段基線有多少來自環境雜訊。

⚠️ `nf` 的白雜訊假設在窄頻干擾下不成立，所以要跟 `comb`/`lms` 一起用。

### ⚠️ 降噪救不了 chou

chou 的乾淨錄音上開任何演算法都是 68–69%（基準 69.5%）。
他的問題是**手部訊號振幅只有別人的 1/4~1/12**，不是雜訊。

## 4. 沒有採用的做法

| 做法 | 為什麼沒做 |
|---|---|
| 提高陷波器的 Q | 更窄的凹陷擋不住有頻寬的干擾；而且市電會漂移 |
| 頻譜相減（spectral subtraction） | 與 comb+lms 功能重疊，但失真風險更高（相位重建） |
| 獨立成分分析（ICA） | 需要足夠多的通道（7 條偏少），且**不是因果的**，即時做不到 |
| 加硬體參考電極 | 最有效，但需要改硬體，不在這次範圍 |
| 直接在實驗室重錄訓練資料 | ★ **這仍然是最該做的**，見 §7。這次做的是不需要重錄的那條路 |

## 5. 實作上最重要的一件事：區塊不變性

⚠️ **每個演算法都必須「輸出與外部怎麼切塊無關」。**

本專案最貴的一個坑：離線與即時各有一份前處理實作，
產出訊號相關係數只有 0.85，訓練 99.6% 全對、即時重播剩 58%。
修法是**只留一份實作**（`StreamFilter`）。

所以這次新增的每一級都掛進同一個 `StreamFilter`，並逐一驗證：

```
分塊餵（每塊 100 樣本，即時）vs 整段餵（4000 樣本，離線）
→ 相對誤差必須是 0
```

**兩個在這關被抓到的 bug：**

| 演算法 | 第一版的錯 | 後果 | 修法 |
|---|---|---|---|
| `lms` | 用區塊平均更新權重一次 | 分塊 vs 整段差 **2%** | 改成**逐樣本**更新 |
| `wavelet` | 直接對傳進來的區塊做 SWT | 分塊 vs 整段差 **91%** | 固定內部分塊 + 歷史緩衝 |

修好之後全部組合都是**逐位元相同**（相對誤差 0.0e+00）。

★ 如果沒做這個驗證，`wavelet` 會在離線評估看起來正常、
　 上機之後行為完全不同 —— 而且**不會報錯**。

## 6. 計算成本（每 50 ms 區塊，預算 50 ms）

### 單獨每一級（只算濾波那一段）

| 設定 | 耗時 | 佔預算 |
|---|---|---|
| 關閉 | 0.11 ms | 0.2% |
| `car` | 0.24 ms | 0.5% |
| `comb` | 0.44 ms | 0.9% |
| `lms` | 1.55 ms | 3.1% |
| `wavelet` | 4.37 ms | 8.7% |

### 端到端每視窗（含特徵抽取與模型，`final_v6_split`）

| 設定 | 中位 | p95 | **p95−中位（抖動）** | 佔預算 |
|---|---|---|---|---|
| 關降噪 | 5.94 ms | 7.47 | 1.54 ms | 11.9% |
| **`lms+nf`（建議）** | **7.52 ms** | 8.01 | **0.49 ms** | 15.0% |
| `comb+lms+nf` | 7.81 ms | 8.62 | 0.81 ms | 15.6% |
| 全開（含 wavelet） | 11.91 ms | 12.56 | 0.65 ms | 23.8% |

**降噪增加 +1.58 ms。** 端到端延遲是 **1.43–2.88 s**（視窗+序列+三道閘主導，
見 `../../pipeline_2026-09-01/延遲分析.md`），所以這是**端到端的 +0.1%** —— 體感不存在。

★ 抖動反而**變小**（1.54 → 0.49 ms）：LMS 的逐樣本迴圈每塊工作量固定，
　 而原本的抖動主要來自 scipy 濾波的不規則配置。即時控制怕抖動不怕平均。

**計算成本不是選擇降噪演算法的考量。**

## 6.1 ⚠️ 關於用 GPU（內顯 / XPU）加速

單次視窗 7.52 ms 的拆解（`lms+nf`）：

```
串流濾波（scipy/numpy，含 lms）   1.58 ms   ← numpy/scipy，上不了 GPU
特徵抽取（numpy，120 維）         ~5.2 ms   ← numpy，上不了 GPU
標準化 + 序列緩衝                 0.26 ms   ← 上不了 GPU
純模型前向（torch）               0.75 ms   ← ★ 只有這段能上 GPU（10%）
```

**模型只佔 10%。** 就算 GPU 把它變成 0，總時間 7.52 → 6.77 ms，
對端到端 1500 ms 而言是 **0.05%**。

而且大概率會**更慢**：模型只有 17,530 參數、batch=1，
kernel launch 與主機↔裝置傳輸的固定開銷通常比 0.75 ms 的運算還大。
更糟的是它會**增加抖動** —— 本專案選 tiny 而非 zhao 的理由之一
就是 p95−中位小一半（0.064 vs 0.134 ms）。

→ `--device xpu` 這個旗標有留著，**但不是給你用的，是給你量的**。
　 量法：`--idle-test 60` 或重播，比較**中位與 p95** 而不只是中位。

→ 真正想縮短延遲的話，槓桿在那三道閘
　 （`MIRROR_MIN_HOLD` 0.5s + `dwell` 0.25s + 投票 0.15s = 0.9s），不是計算。

## 7. ⚠️ 降噪不能取代的事

這次做的是「不用重錄」的那條路。但有兩件事降噪解決不了：

1. **在實驗室錄一份 chou / leon 的資料。**
   目前所有離線數字都來自安靜環境，部署在吵的實驗室 ——
   兩者對不上，而且**無法驗證降噪在真實實驗室雜訊下的效果**
   （本文件的加噪測試用的是模擬注入，不是真實實驗室錄音）。
   這是目前最該補的一份資料。

2. **chou 的手部電極位置。**
   他的 ch5/ch6/ch7 絕對振幅只有別人的 1/4~1/12，
   而 60Hz 與底噪都是全場最低（= 貼得很牢）。
   那是**位置**或**出力**問題，降噪幫不上忙。
