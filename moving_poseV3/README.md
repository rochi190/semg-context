### 為什麼要做降噪

訓練資料錄在**安靜**的地方，機械手臂放在**實驗室**（電器多、雜訊大）。
這也解釋了先前「離線量測與實機觀察對不上」——
`chou` 離線量到的是 hand 最差，實機看到的卻是 elbow 不好觸發
（見 `../results/subject_compare/README.md`）。

★ 降噪的目標**不是**讓訊號變好看，是把「吵環境的訊號」
　 映射回「乾淨環境的樣子」，好讓乾淨資料訓練的模型仍然適用。

## 2. ★ 降噪：哪些該開、哪些不該

每個演算法都跑了兩個測試（方法與完整數字見 `docs/denoise.md`）：

```
① 乾淨訊號中性：開了不能讓乾淨錄音的準確率變差   ← 底線
② 加噪可回復  ：加了實驗室型雜訊要能救回來        ← 有用的證據
```

### 測試結果

**第一階段**（gary，乾淨訊號中性，全 6 個候選）：

| 演算法 | 乾淨全對 | Δ | 判定 |
|---|---|---|---|
| （關閉） | 99.5% | — | 基準 |
| `lms` | **99.5%** | **0.0** | ✅ |
| `nf` | 99.2% | −0.3 | ✅ |
| `comb` | 98.8% | −0.7 | ✅ |
| `car` | 84.5% | **−15.0** | ❌ |
| `wavelet` | 65.0% | **−34.5** | ❌ |
| `hampel` | 63.9% | **−35.6** | ❌ |

**第二階段**（三位受試者，Δ 相對關閉）：

| 演算法 | 乾淨 Δ 平均 | **加噪 15µV Δ（gary/neil/chou）** | 平均 |
|---|---|---|---|
| `comb` | −0.63 | +5.8 / +7.9 / +3.9 | +5.87 |
| `lms` | **−0.13** | +8.0 / +5.5 / −0.7 | +4.27 |
| `nf` | −0.70 | +13.6 / +4.5 / +0.0 | +6.03 |
| `lms+nf` | −0.93 | +16.0 / +8.4 / +0.3 | +8.23 |
| **`comb+lms+nf`** | −1.07 | **+17.2 / +10.0 / +1.6** | **+9.60** |

**→ `--comb --lms --nf`**：三個人都最高，乾淨訊號只多付 0.14 pp。

⚠️ **我先前只看 gary 一人時建議 `lms+nf` 並說「nf 單項最強」，
三人資料把兩句都推翻了** —— nf 在 neil 只有 +4.5、chou +0.0。
單一受試者的最佳解可能只是那個人的特性。

⚠️ **降噪救不了 chou**（加噪後 51.3% → 最好 55.2%）。
他的手部訊號只有 4.7 µV，加 15 µV 雜訊等於被埋掉。

### ⚠️ 三個被淘汰的，原因不一樣

**`hampel` 不是壞演算法 —— 是我分類錯了。**
模型是 `use_hampel=False` 訓練的，推論時打開等於**訓練/推論前處理不一致**。
要用它必須**重新訓練**，不是切換旗標。這條規則在本專案寫進 bundle 就是為了防這個。

**`car` 的失敗是真的。** 遠端只有 3 個通道、近端 4 個，
減掉組內平均會把真實的肌電也減掉（elbow 99.6% → 75.4%）。
通道數太少，CAR 這個方法不適用。

**`wavelet` 的軟閾值會壓掉所有小幅訊號** —— 包含 chou 那種本來就很小的肌電。

★ 三個都留在程式裡、都可以開，只是**預設關閉且有警告**。
　 你可以自己驗證上面的數字。

| | V5（`final_v5_split`） | **V6（`final_v6_split`）** |
|---|---|---|
| 錄音 | 7 份 | **9 份** |
| 受試者 | neil, gary | **neil, gary, chou, leon** |
| 貼片場次 | 3 | **5** |
| 架構 | split（分離編碼器） | 同左，沒動 |

| **留一受試者（跨人）** | — | **73.7% ± 12.2%** |

| **leon_20260911** | **85.9%** | 84.1% | 93.1% | 99.3% |

| | **77.5% ± 11.5%** | 85.8% | 87.9% | 93.5% |

### 逐折：留一受試者（4 折，真正的跨人）

**73.7% ± 12.2%**（hand 平衡 77.3%、elbow 90.2%、shoulder 92.7%）

⚠️ 這才是「**換一個從沒看過的人**」的期望值。比留一場次低 3.8 pp，
合理 —— 跨人比跨場次難。

### ⚠️ 加入 chou/leon 的代價

平均上升（73.0 → 77.5），但 **neil 的 `21-54-56` 那一折從 67.1% 掉到 57.1%**
（hand 平衡只剩 50.0%）。這正是先前警告過的風險：
把「電極沒貼好」學成「這個人的特徵」。

→ **一定要現場 A/B，不要直接取代：**

```bash
python run_compare.py COM10 --a final_v6_split --b final_v5_split
```

⚠️ **不要分兩次跑再比** —— 場次與貼片的變異遠大於模型差異。

## 4. 命令列旗標

### 降噪

| 旗標 | 說明 |
|---|---|
| `--lms` | ★ 自適應市電消除。不挖頻譜洞、會追市電漂移 |
| `--nf` / `--noise-floor` | ★ 雜訊底噪補償。吵環境下校準尺度 α 會被墊高 → 所有相對特徵被壓扁 → 該自由度不觸發 |
| `--comb` | 60Hz 諧波梳狀陷波（120/180/…/420Hz） |
| `--car` | ⚠️ 分組共同平均參考。乾淨訊號上 −15.0 pp |
| `--wavelet` | ⚠️ 小波軟閾值。乾淨訊號上 −34.5 pp |
| `--hampel` | ⚠️ 突波抑制。與訓練設定不符，−35.6 pp |
| `--denoise a,b,c` | 一次指定多個，例 `--denoise comb,lms` |
| `--device xpu` | ⚠️ 換推論裝置。模型前向只佔每視窗 10%，換 GPU 省不到端到端 0.1%，且 batch=1 小模型通常更慢、抖動更大。留著是給你自己量的，見 `docs/denoise.md` §6.1 |

**降噪的計算代價**：`comb+lms+nf` 每視窗 5.94 → **7.81 ms**（預算 50 ms），
端到端延遲 1.43–2.88 s 只增加 **0.1%**。抖動反而從 1.54 → 0.49 ms 變小。

### 沿用 V2 的

| 旗標 | 建議 |
|---|---|
| `--bias elbow=3` | ★ elbow 最弱，這是整條曲線最划算的一點 |
| `--dwell hand=5` | ★ 擋掉移動過程的中間狀態 |
| `--conf` | **沒用** —— 信心值在對與錯時都飽和在 1.00 |
| `--idle-test 60` | 接手臂前必做的靜止誤觸發測試 |

## 6. ⚠️ 降噪不能取代的兩件事

1. **在實驗室錄一份 chou / leon 的資料。**
   目前所有離線數字都來自安靜環境。本文件的加噪測試是**模擬注入**，
   不是真實實驗室錄音 —— 降噪在真實實驗室的效果**尚未驗證**。
   這是目前最該補的一份資料。

2. **chou 的手部電極位置。**
   他的 ch5/ch6/ch7 絕對振幅只有別人的 1/4~1/12，
   而 60Hz 與底噪都是全場最低（= 貼得很牢）。
   那是**位置**或**出力**問題，降噪幫不上忙。
   驗證方法：請他用力捏到底錄 30 秒，看 ch6/ch7 的 p95 能否上到 30 µV。
