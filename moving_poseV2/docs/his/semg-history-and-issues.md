## 2. V1 的問題（沿用 SoftPINCH 的那一版）

### 2.1 資料與標籤

#### 🟠 沒有 trial 時間戳，只能猜邊界 ✅
SoftPINCH 的 `_segment_trials` 把每個 trial 固定切三等分（rest / contract / release），
這**要求精確的 trial 邊界**。我們的錄音沒有任何時間戳，只能用 autocorrelation 猜週期再推邊界。

**實際傷害**：一度算出模型只有 **6.1%**，判斷成「模型在我們資料上失效」。
重新對齊邊界後，**同一份資料、同一個模型變成 92.4%** —— 差 86 個百分點，
那個結論**完全是標籤對齊誤差製造的假象**。

#### 🟠 一檔一手勢 → 手勢與錄音檔完全共線 ✅
每個錄音只做一個手勢（`indexgary_20260711_00-17-09.csv` 整檔都是 index），
標籤來自檔名 → 「手勢」與「錄音檔身分」統計上完全共線。

> 沒有任何切分方式能證明模型學到的是肌電形態，而不是「認出這是哪一個錄音檔」。

實測（4 類，亂猜 25%）：

| 評估方式 | 電極位置 | RandomForest | CNN+BiLSTM+Attn |
|---|---|---|---|
| 隨機切窗 80/20 | 固定 | **99.9%** | val_loss ≈ 0.0000 |
| within-session（前70%訓/後30%測） | 固定 | **93.0% ± 4.1%** | — |
| within-subject（每手勢留 1 檔） | 重貼過 | 24–39% | — |
| LOSO（留一人） | 重貼過 + 換人 | 23.5–45.0% | **28.5% ± 3.7%** |

逐檔 leave-one-file-out：18/28 檔低於 10%。但這**不能**解讀成「這 18 檔壞掉」——
每個手勢每個 session 只錄一次，「同手勢不同檔」永遠等於「不同電極位置」，兩個解釋分不開。

**關鍵反證**：SoftPINCH 預訓練模型（16 位受試者訓練，從未見過我們任何檔案）
在同一批資料上手指判別率 **84%**。
→ 判別資訊確實存在，問題不在訊號、不在架構，**在於 28 個「一檔一手勢」錄音無法支撐從零訓練**。

#### 🟠 固定循環錄製 → 模型可能只學到「循環到第幾秒」 ✅
單一姿勢一直循環（出力 3s → 放鬆 3s → 休息 3s）。固定週期下，
「現在是第幾秒」與「現在是什麼相位」是同一件事 —— 模型可以完全不看肌電，只數時間就得高分。
這與共線問題疊加，是 93% → 28.5% 落差的另一半來源。

#### 🟠🟣 沒有 metadata 就進 pipeline ✅
`CLAUDE.md` 明文規定「沒有 metadata 的資料不要進 pipeline」，但我把 28 個檔案全部丟進去，
沒有先確認哪些可用。使用者後來指出「很多都不是能用的」——那批數字有一部分本來就被壞檔案拖著。

#### 🔴 相位標籤：三次嘗試全部失敗 ⬜（改變策略而非硬解）

| 嘗試 | 做法 | 結果 |
|---|---|---|
| 1 | `median + 3·MAD` 門檻抓 burst | **8/28 檔偵測到 0 個 burst**。公式假設「大部分時間在休息」，活動佔比高時 median 落進活動區、MAD 膨脹，門檻**比 p95 還高** |
| 2 | 改用百分位數門檻 | 0-burst 解決（0/28），但 burst 數 **9–149 個**、長度 **0.7–18.4s**。根因**不在門檻而在相位定義**：EMG burst 是「垂直上升 → 高原緩慢衰減 → 落下」，`onset` 只有 1–2 樣本，**高原衰減被判成 `release`** → release 29% vs hold 3% |
| 3 | 每通道 active/rest 多標籤（Lee et al. 風格） | ch2−ch3 差值：index **−0.082**、thumb **+0.146** —— **方向完全反了**，標準差 0.15–0.20 重疊嚴重 |

但同一批資料上 SoftPINCH 手指判別率 84% → 判別資訊在**波形形態**裡，簡單門檻抓不到。

**V1 的結論**：放棄相位，只用「手勢（檔名）+ 有沒有在動」。
**V2 的解法**：相位不再需要推導，直接從 cue 檔讀。

### 2.2 正規化

#### 🔴 z-score 對校準期組成高度敏感 ✅
SoftPINCH realtime checkpoint 附 `mu.npy` / `sigma.npy`（絕對 mV），
模型輸入前做 `(env_buf - mu) / (sigma + 1e-8)`。

把校準期的休息佔比從 30% 掃到 90%：

| 休息佔比 | 30% | 90% |
|---|---|---|
| 手指判別率 | ~88% | ~65% |

**漂移 ±8.8pp** —— 使用者只要休息久一點準確率就變了，這不是能接受的部署特性。
原因：$\sigma$ 是二階矩，出力段的高振幅樣本貢獻與振幅平方成正比，
「出力佔多少比例」直接改變 $\sigma$。中位數與 MAD 只看排序，敏感度低得多。

其他實測：
- 校準**必須包含出力**：只錄休息 67.5%，含出力 84.5%
- 校準長度：15s = 79.6%、45s = 86.0%、60s = 87.1%、90s 之後持平
- 校準手勢要對：同手勢 79.2% > 兩手勢 70.7% > 錯手勢 54.7%
  （⚠️ 「兩手勢」那組有混淆：兩段獨立錄音接起來會讓 sigma 膨脹 1.4–2.4×）

#### 🔴 跨通道比值在 z-score 後會爆炸 ✅
想用「食指/拇指能量比」當判別特徵，z-score 後取比值、分母趨零 → 數值爆炸，
某個檔案掉到 **47%（低於亂猜）**。改成逐通道各自正規化，又把判別訊號一起消掉：
**Cohen's d 從 3.88 掉到 0.12**。

#### 🔴 無法從原始碼確認 SoftPINCH 離線用什麼正規化 ⬜
`load_and_visualize_data.py` 沒有公開。只能反推：per-file z-score 能重現他們宣稱的 99.4%
（我們算到 98.65% / 99.07%），不做正規化則全部預測 Rest。

### 2.3 模型與架構

#### 🔴 7 類 realtime checkpoint 在我們資料上等於亂猜 ✅

| 指標 | 數值 |
|---|---|
| 準確率 | **32.3%**（亂猜 33%） |
| 預測分布 | **77.6% 的預測都是 Index**，不管真實手勢是什麼 |

乾淨對照（同一份資料、同一套前處理）：

| checkpoint | 訓練資料 | 我們資料上的準確率 |
|---|---|---|
| 5 類離線 | 16 位受試者 LOSO | **84%** |
| 7 類 realtime | **只有 subject_0** | **32%** |

→ 泛化能力來自**訓練受試者的多樣性**，不是架構。

還發現兩件事：
- `classification_pipeline.py:2398` 的 `MAX_NUM_TRIALS = 1` → realtime 超參數是**一次隨機 SHERPA draw**（離線版是 70 trials）
- `classification_pipeline.py:2057-2073` realtime 標籤是**斜率式**（`REST_THRESH=0.003`，`slope>0`→contract），位置式版本被註解掉
  → 兩個 checkpoint 學的是**不同的任務**（相位分類 vs onset/offset 偵測），不是同一個模型的兩種設定

#### 🔴 5 類互斥 → 無法表示「同時彎曲」 ✅
5 類是互斥 softmax，沒有 pinch；7 類有 pinch 但如上不可用。
使用者的核心需求「同時彎食指和拇指」在 V1 表達不出來。

#### 🔴 3 秒視窗，延遲 0.70s 且無法靠縮短視窗改善 ✅

| 來源 | 時間 | 佔比 |
|---|---|---|
| 模型（3s 視窗） | 0.70s | **70%** |
| 後處理（3 窗 × 100ms） | 0.30s | 30% |

（我一度說「延遲主要來自 5 窗多數投票」，**這是錯的**，實測後已更正。）
縮短視窗會掉準確率，因為模型沒見過那個長度 —— 不是延遲問題而是分布外問題。

#### 🔴 RMS 包絡線是有損摘要 ✅
RMS 把 500 個樣本壓成 1 個數字，**頻譜資訊全部消失**：MNF/MDF/PKF/bandwidth/MFCC 一個都算不出來。
肌纖維傳導速度與募集模式就藏在那裡。論文說「提前幫模型濾特徵、減輕模型負擔」是對的，
但沒說那是**有損**的。

| 論文 | 進模型的東西 | 代價 |
|---|---|---|
| SoftPINCH | 40 Hz RMS 包絡線（120 點） | 頻譜資訊全部丟掉 |
| Lee 2024 | bandpass + 整流（保留 2000 Hz） | 輸入大，但頻率內容還在 |
| Zhao 2025 | 從原始波形算多域特徵 | 時域 + 頻域 + 倒頻譜都保留 |

#### 🔴 LSTM 只取最後隱狀態 ✅
SoftPINCH 是單向 LSTM 取最後一步。動作若不發生在序列結尾就吃虧。

#### 🟣 我把目標設計錯了 ✅
我寫了 `simplify_predicted()` 把 5 類輸出收斂成 3 個夾爪狀態（open/close/hold），
**丟掉了 Index/Thumb 的區分** —— 那正是使用者要的東西。
使用者直接指出：「我要做的是手勢分類，所以你要我只分類一隻?」

**教訓**：模型輸出就是手勢/姿勢類別本身，致動器映射放在**下游**，不在模型輸出層做壓縮。

### 2.4 評估方法

#### 🔴 隨機切窗 99.9% 是洩漏 ✅
視窗步進 50ms、序列涵蓋 0.95s → 隨機切分時
**幾乎每個測試序列在訓練集裡都有 95% 重疊的鄰居**。加上一檔一標籤，模型只要認出檔案就滿分。
鐵證：**所有折的 `val_loss ≈ 0.0000`**。

> 任何論文只報隨機切分的數字，都要先問它有沒有處理這件事。

#### 🔴 只報一個數字 ✅
SoftPINCH 論文只報一個準確率，我們花了很多力氣才搞清楚那對應哪個設定
（per-file z-score + 位置式標籤 + 16 人 LOSO）。

#### 🟣 within-subject 切分會抽走整個類別 ✅
```python
te_files = set(rng.choice(fs, size=max(1, len(fs) // 4), replace=False))
```
CBW1 只有 4 檔（每手勢 1 檔），抽走 1 檔 → **該手勢在訓練集完全消失** → 必然 0%。
三個受試者**都恰好 0.0%** 就是這個 bug 的指紋（三人獨立完全 0% 機率上不可能）。

**教訓**：異常整齊的數字（0.0%、100.0%）優先懷疑 bug，不要先解釋成模型行為。

#### 🟣 品質門檻用錯代理指標 ✅
用「動態範圍」當訊號品質門檻：
- 與誤觸發率相關只有 **r = −0.40**
- 誤觸發 <5% 的檔案範圍 2.1–25.0×；≥5% 的檔案範圍 2.2–6.5× → **完全重疊**，沒有判別力

**修法**：改成**直接量測** pipeline 的誤觸發率／偵測率／延遲，不用代理指標。

## 3. V2 設計演進：每一次被推翻的推理過程

### 3.1 v2.0：放棄相位，只用可靠標籤（後被 cue 協定取代）

當時的結論表：

| 資訊 | 可靠度 | 用途 |
|---|---|---|
| 手勢（來自檔名） | ✅ 100% | 訓練目標 |
| 有沒有在動（三通道合併能量百分位門檻） | ✅ 穩健 | 篩選訓練視窗 |
| ~~相位（onset/hold/release）~~ | ❌ 無法可靠推導 | 放棄 |
| ~~每通道活化~~ | ❌ 與手勢反相關 | 放棄 |

結果 **77,998 個訓練視窗**（grasp 28,464 / pinch 21,140 / thumb 15,062 / index 13,332）。
原本規劃的雙頭（Head A 每通道多標籤 + Head B 手勢多類）**放棄 Head A**，改為單一手勢頭。

**v2 實測結果，推翻了這條路**：

| 評估方式 | 電極位置 | RandomForest | CNN+BiLSTM+Attn |
|---|---|---|---|
| 隨機切窗 80/20 | 固定 | **99.9%** | val_loss≈0 |
| within-session | 固定 | **93.0% ± 4.1%** | — |
| within-subject | 重貼過 | 24–39% | 0%（切分 bug，已修） |
| LOSO | 重貼過 + 換人 | 23.5–45.0% | **28.5% ± 3.7%** |

**結論：在錄製協定修正之前，繼續調模型架構或超參數不會有幫助** ——
93% 與 28% 的落差不是模型容量問題。

### 3.2 v2.1：7 通道 + cue 協定，舊資料全部棄用

`C.USE_LEGACY_DATA = False` —— 28 個舊錄音預設不進 pipeline（手勢與錄音檔共線，無法證明模型學到什麼）。

合成資料端到端驗證：cue 標籤秒數完全吻合、120 維特徵 0 個 NaN/Inf、trial 分組 5 折 100.0%、LOSO 100.0%。
⚠️ 100% 是因為合成訊號的通道模式乾淨可分，**只驗證管線正確，不預測真實準確率**。

### 3.3 v2.2：從互斥多類改為多輸出

互斥多類要為**每一種組合**開一個類別，組合數指數成長，而且**訓練時沒見過的組合永遠預測不出來**。

當時的配置（4 DOF）：

| 自由度 | 狀態 | 對應肌群 |
|---|---|---|
| index | rest / flex | 食指 (+曲腕肌) |
| thumb | rest / flex | 拇指 (+曲腕肌) |
| elbow | rest / flex / ext | 二頭 / 三頭 |
| shoulder | rest / flex / ext | 三角 / 背闊 |

10 動作 × 5 次 = 50 trial ≈ 7.7 分鐘/次錄音。

### 3.4 v2.3：狀態數依「量得到什麼」決定

**曾經改成 (3,3,3,3) 又改回來。** 動機是「致動器需要明確的張開指令，否則機械手臂不會收回休息位置」——
控制需求是對的，但解法錯了：手指硬加一個 ext 態，等於要模型去分辨**訊號上完全相同**的兩段資料。

> **狀態數由訊號決定，語意由控制層決定** —— 不需要為了對稱把兩者綁在一起。

正確解法放在控制層（`C.ACTUATOR_SEMANTICS`）：手指 `rest` → 夾爪張開；肘/肩 `rest` → 停在現在角度。

### 3.5 v2.4：DOF 依肌群解剖分離度重新切分（(4,3,3)）

#### 等長收縮 + 固定姿勢（後被推翻）
當時要求錄製時用等長收縮，否則 3 秒內肌肉長度與速度一直變，500ms 視窗內訊號非平穩，
破壞所有頻域特徵的前提。

> 教授要求的 IMU 是對的，**但只在姿勢自由變動時才成立**：IMU 的作用是把「出力」與「肌肉長度」解耦。
> 姿勢固定時肌肉長度是常數，沒有東西需要解耦 —— **固定姿勢與 IMU 解的是同一個問題，成本低得多**。
> 其他論文沒用 IMU 是因為他們用外骨骼/固定架鎖住了姿勢。

#### ch2 改貼三角肌前束
原本誤以為 ch2 在前束，實際在中束。

| 三角肌 | 動作 |
|---|---|
| 前束 | 肩屈曲（往**前**舉）← 目標場景「往前伸手取物」 |
| 中束 | 肩外展（往**外**舉） |

一顆電極分不出兩者。要同時支援兩個平面必須 ch2 前束 + ch8 中束，但兩者相鄰、串音風險高。目前 ch8 保留不用。

#### 手部改成單一 categorical DOF
$$\text{捏（對掌）} \neq \text{食指彎曲} + \text{拇指彎曲}$$

捏用的是拇指對掌肌群 + 食指屈肌 + 額外的穩定性共同收縮，是**不同的協同模式**。
標成 `(index=flex, thumb=flex)` 等於要模型把兩者映射到相同輸出 → 失去區分能力。
加上 3 顆遠端電極（前臂屈肌群高度重疊 + ECG 型電極面積大）本來就解析不出 2 個獨立手指自由度。

→ `hand ∈ {rest, index, thumb, pinch}`，義肢領域對 grip type 的標準做法。

### 3.6 v2.5：標「維持中的姿勢」而非「動作方向」（(4,2,2)）★ 現行

#### 為什麼推翻等長協定
等長固定姿勢是為「外部致動器」設計的。使用者指出關鍵問題：
外骨骼一旦分擔負載，使用者 EMG 會掉到訓練資料裡從未出現的水準 → 分類器讀到 rest →
停止協助 → 手臂下墜 → 振盪。固定姿勢的資料完全無法涵蓋那個狀態。

#### 但「標移動方向」也不對

| 問題 | 為什麼無解 |
|---|---|
| 「保持」與「放鬆」都要塞進 `rest` | 兩者是振幅的**兩個極端**（中等持平 vs 接近零），類別內變異過大 |
| 「放下」標成 `ext` | 放下活躍的是**三角肌離心收縮**（煞車），不是背闊肌 → 標籤與生理不符 |
| 補救要加 `hold` 狀態或彈力帶 | 複雜度爆增，`ext` 訊號仍然很弱 |

#### 解法：標「現在維持在什麼姿勢」
使用者的關鍵洞察：**移動過程很短**（手指 ~0.3s、手臂 ~0.5s），相對於維持的時間可忽略 ——
就像手部一直以來都只標「食指是否彎曲」，不標彎曲的過程。三個問題同時消失，丟棄比例約 50%。

#### 為什麼沒有 `ext` 狀態
伸展姿勢（手臂後伸、肘過度伸直）在重力下幾乎沒有負載：
$\tau_{\text{需要}}(\theta_{\text{ext}}) \approx 0 \Rightarrow \text{EMG} \approx \text{EMG}_{\text{rest}}$。
要把「主動往後壓」做成指令必須加阻力（彈力帶）—— 另一種設計，成本更高。

#### 硬性前提：手臂必須懸空
維持姿勢時手臂靠桌面、扶手或貼死身側 → 重力被外物支撐 → EMG 消失 → 判成 rest → 機械手臂放下。

> **誠實定位**：等長 → 動態 → 姿勢維持，這三次改動**都沒有解決外骨骼的負載分擔問題**。
> 那需要比例控制或 human-in-the-loop 重訓。現在的協定符合的是「機械手臂 + 位置鏡像」這個專案。

#### 結果對照

| | v2.4 | v2.5（現行） |
|---|---|---|
| 狀態數 | (4,3,3) | **(4,2,2)** |
| 組合數 | 36 | 16 |
| cue 動作 | 11 | **8** |
| 錄製時間 | 9.3 分鐘 | **6.5 分鐘** |
| 模型參數 | 11,723 | 11,625 |
| 控制範式 | 速率控制 | **位置鏡像** |

### 3.7 v2.6：固定順序 + preview；架構對照 baseline

#### 錄製順序改成固定（使用者決定）
使用者的反駁：「如果有殘留，你打亂順序，每次不一樣，殘留也會不一樣，一樣會有問題。」

**這個反駁一半正確，把精確的差別寫下來**：

| | 殘留與標籤的關係 | 模型會怎樣 |
|---|---|---|
| 固定順序 | **完全相關**（B 永遠跟在 A 後面） | 會去利用它（能降 loss）→ 學到的規則有**系統性偏差** |
| 打亂順序 | **不相關** | 利用不了 → 只是增加類別內**變異** |

打亂的作用是把「偏差」轉成「雜訊」，不是消除殘留。
**但實務上使用者是對的**：每個姿勢只重複 5 次，5 次平均不掉，
換來的動作品質下降（受試者無法預期、容易做錯）可能不划算。

⚠️ **一個做不到的測試**：原本想用「拿維持段特徵去預測前一個姿勢」當否定對照，
但固定順序下前一個姿勢由當前姿勢**決定**，準確率必然 100%，測不出東西。

#### preview：把「讀字判斷」與「身體移動」分開
實際錄製時發現 `prepare` 2.0s 不夠讀字 + 判斷 + 移動到位。
解法不是單純延長 prepare（受試者會提前擺好姿勢後空等，白白累積疲勞），而是**拆成兩段**。
`preview` 必須**丟棄**：受試者已知道下一個是什麼、可能提前緊張，留在 rest 裡會汙染「完全放鬆」這一類。
代價：丟棄比例從 50% 升到 **65%**，錄製 6.5 → 7.5 分鐘。

#### 架構對照 `--arch zhao`
「為什麼不用論文的模型」不能用推理回答，要用**同一份資料、同一套評估流程**的數字回答。

合成資料上的初步結果：

| 架構 | 參數 | CPU 中位數 | 抖動 | trial-kfold | LOSO |
|---|---|---|---|---|---|
| Zhao 論文 | 355,784 | 0.678 ms | 0.136 ms | 99.8% | 99.8% |
| 本專案 | 11,625 | 0.555 ms | 0.081 ms | 99.6% | 99.6% |

⚠️ **合成資料上兩者打平（都飽和），這個比較無法區分架構優劣。**

#### SEQ_LEN 消融

| SEQ_LEN | 上下文 | 總延遲 | trial-kfold | LOSO |
|---|---|---|---|---|
| **1** | 0.50s | **0.70s** | 100.0% | 100.0% |
| 3 | 0.60s | 0.80s | 99.9% | 100.0% |
| 10 | 0.95s | 1.15s | 99.6% | 99.6% |

⚠️ **不能直接採信**：合成資料在維持段是嚴格平穩的（固定振幅生成），對 SEQ_LEN=1 天生有利。
真實 sEMG 有波動、疲勞漂移、姿勢微調，時序平均可能才有價值。

## 4. 實作過程踩到的 bug 全紀錄

### 4.1 ★ 兩個「離線 99.6% / 即時 58%」的 bug

兩個都屬於**訓練與推論走了不同路徑**。

#### bug 1：尺度來源不一致（1.27×）
訓練用「整檔 MAD」、推論用「開頭休息段 MAD」，系統性差 **1.27×**（休息段沒有出力，MAD 較小）
→ 推論時所有振幅特徵被放大 1.27×，分布偏移。

| | 全對率 |
|---|---|
| 離線訓練（trial 分組 5 折） | 99.6% |
| 即時重播（同一個模型、同一份資料） | **58.0%**（97% 的預測都變成 rest） |

> 我原本宣稱「MAD 夠穩健，校準餵任意訊號都行」——**這被實驗推翻了**。
> **穩健性不能替代一致性**：再穩健的統計量，只要訓練和推論算在**不同性質的區段**上，就一定會偏移。

#### bug 2：前處理有兩份實作（相關係數只有 0.85）
離線 `filter_causal` = notch → bandpass → **Hampel**；即時 `StreamFilter` = notch → bandpass（**沒有 Hampel**）。
訊號相關係數 0.85，MFCC3 差到 600%。而且離線那個 Hampel 用**置中視窗**，
會吃到未來 100 個樣本 —— 函式叫 `filter_causal` 但其實非因果。

修法（結構性，不是靠記得同步）：
- Hampel 改**因果**（`origin=K//2`，視窗 [i−200, i]）
- **只留一份實作**：`filter_causal()` 就是把整段餵給 `StreamFilter`
- Hampel 是兩段式，串流要保留 **2×(K−1)** 個歷史樣本，只留 K−1 會讓 MAD 視窗吃到 padding 過的 med

驗證：區塊 100/250/1000 樣本三種餵法，離線與串流 **max 差 0.000e+00**（逐位元相同）。
修後即時重播全對率 58.0% → **91.9%**。

### 4.2 ★ 序列跨越 go→rest 邊界（實測 18% 訓練序列受影響）

`dataset.py` 的分組鍵是 `<檔名>#<rep>`，但**一個 trial 含兩段不連續的有標籤區間**：

```
preview(丟棄) → prepare(丟棄) → go(標姿勢) → return(丟棄) → release(標 rest)
                                 └────────── 同一個 #rep ──────────┘
```

`make_sequences` 只看**陣列相鄰**、不看時間，於是把「go 段最後幾個視窗」與「release 段最前幾個視窗」黏成一條序列。

| | 修正前 | 修正後 |
|---|---|---|
| 含多種標籤的群組 | **96 / 96** | 0 |
| 內含多種標籤的序列 | **891 / 4941（18.0%）** | **0** |

兩個危害：標籤取序列最後一個視窗 → 這些序列標成 `rest` 卻含最多 9 個**姿勢**視窗；
被黏起來的兩個視窗實際相隔 1.5s 以上，卻被當成相隔 50ms → **偽造的時間連續性**。

**修法：分出兩個鍵，各司其職**

| 鍵 | 用途 | 值 |
|---|---|---|
| `segment` | `make_sequences` 堆疊 | `<檔名>#<rep>#<區間序號>` |
| `trial` | `trial_group_splits` 交叉驗證 | `<檔名>#<rep>` |

### 4.3 config 秒數的硬約束與 `validate()`

一條序列涵蓋 `WIN_SEC + (SEQ_LEN-1)×STEP_SEC = 0.95s`，
任何有標籤的段落**扣掉兩端 margin 後**必須 ≥ 0.95s。

`make_sequences` 對「視窗數 < SEQ_LEN」的群組是 `continue` —— **不報錯、靜默丟掉**。
參數設錯不會有任何徵兆，直到發現某個類別完全沒有訓練資料。

⚠️ `segment_report` 一開始用秒數算視窗數，`(2.3-0.5)/0.05` 在浮點下是 `35.999…`，
`int()` 之後少一個視窗。改成用**樣本數**算，與 `dataset.build` 的切窗迴圈一致。

`CUE_REST_SEC` 也從 4.5 提到 **5.0** —— 原本 rest 段只剩 0.35s 餘裕，
使用者稍微調一下 preview 就會踩到 0 序列。

### 4.4 margin 改成非對稱，並更正它的理由

原本兩端都是 0.3s，docstring 寫「起始往後縮 → 避開反應延遲」。**那是等長協定的語意**。
現在 `go` 的語意是「你應該已經維持住了」—— 反應時間在 `preview` + `prepare` 就用掉了。

| | 吸收什麼 | 值 |
|---|---|---|
| 起始 | 還沒擺好、還在微調（變異大） | **0.5 s** |
| 結束 | 提前放鬆（通常很短） | **0.2 s** |

### 4.5 Terminal 輸出：Windows 一直換行的根因

單行更新用 `\r` 覆寫，但原本每行 `ljust(190)`。**中文是雙寬字元**，`len()` 只算 1、實際佔 2 欄
→ 一行實際顯示寬度超過 250 欄 → Windows 主控台預設 80/120 欄自動折行
→ `\r` 只回到**最後一行**開頭 → 看起來就是每 0.05 秒印一行新的。

修法：`unicodedata.east_asian_width` 正確算寬度、`shutil.get_terminal_size()` 取實際欄數、
欄位按重要性排序放不下就整項略過、進度條改 ASCII `#`。

### 4.6 v2.5 校準輪修掉的四個 bug

|---|---|---|
| `meta.json` 寫成 **cp950** | Windows 的 `write_text()` 用系統 locale，Linux 端 `json.load` 直接 UnicodeDecodeError | 全部加 `encoding="utf-8"` |

### 4.8 三個尺度不變性錯誤（實測抓到）

用「訊號 ×α，特徵應該不變」當檢驗，掃 α ∈ {0.5, 2, 5, 20}：

| # | 問題 | 數學原因 | 實測偏差 | 修法 |
|---|---|---|---|---|
| 1 | **SSC 非尺度不變** | $(\Delta_1\Delta_2) \ge \epsilon$ 量綱不符：左 mV²、右 mV | **197%** | 門檻改 $\epsilon^2$ |
| 2 | **MFCC1 非尺度不變** | welch 餵未正規化的 $x$，$c_0$ 是能量項 → 平移 $\log\alpha^2$ | 26% | 改餵 $x_s$ |
| 3 | **RSS ≡ RMS** | $\sqrt{\sum x^2}/\sqrt{n} = \text{RMS}$，**數學上完全相同** | 7 維浪費 | 改成 WAMP |

修正後：**0/120 違反尺度不變**（最大偏差 $8.4\times10^{-8}$，純浮點誤差）。

### 4.9 誠實說明：特徵矩陣不是滿秩

200 個獨立視窗算出的特徵矩陣**秩為 97 / 120**，有 23 個線性相依維度。來源：
7 個 `prop_*` 總和恆為 1、`grp_proximal + grp_distal = 1`、
`logr_distal_proximal` 是 `grp_distal` 的確定性函數、5 個 `logr_a_b` 可由各通道 `log_rms` 差得出等。

**這對神經網路無害**（$1\times1$ 卷積會自行學到有效低維表示），
**但若之後改用線性模型或做 PCA，必須先處理。**

### 4.10 陷波器量測假象

用 `freqz` 預設的 512 點網格（間距 3.91 Hz）會量到 −6.4 dB，
因為最近的網格點離 60 Hz 差約 2 Hz，剛好落在陷波邊緣 ——
**這是量測假象，不是濾波器不夠深**（在精確 60 Hz 求值是 −260 dB）。

### 4.11 合成資料無法回答「訊號差異要多大才夠」

原本想用合成資料掃出串音門檻，得到「3% 就夠」。**這個數字沒有意義**：
合成訊號是純高斯雜訊，baseline 0.05 之上加 0.02 等於高 40%，在 1000 樣本視窗上 RMS 估計極穩。
真實 sEMG 的電極漂移、疲勞、姿勢變化、trial 間變異全都不在裡面。
合成測試只證明兩個分支都會動（有資訊 → 100%，無資訊 → 49.7%）。

## 5. 用第一份真實錄音校準協定

第一份真實錄音（gary，40 trial、470s、0 壞幀）分析後，**三個參數是量出來改的，不是憑感覺**。

### 5.1 反應時間：不能假設，只能量

使用者提出「每個人看到 cue 都有反應時間，不能假設時間戳當下就已經在做該姿勢」。

量 `t_reach`（從 prepare 起算到訊號到達維持水準的 90%，**已含反應時間**）：

| | 中位數 | p90 | max |
|---|---|---|---|
| 全部 40 trial | 0.40s | 0.61s | 1.00s |

逐姿勢差異明顯：`index_flex` 0.22s ── `arm_lift` 0.52s（複合姿勢較慢）。

原本想「回收 prepare 的後 1.6s」，**但放棄了** —— 那等於假設「每個人 1.0s 內一定到位」。
**改用加長 `CUE_ACTION_SEC` 3.0 → 4.0s**：資料量增益完全相同（pose 從 28 條序列變 48 條），但**零假設**。

> **原則：協定要吸收變異，不要假設變異不存在。**

### 5.2 rest 類別被汙染（沒人問，但量到了）

以開頭空白段為絕對基線，從 **return 起點**量訊號衰減 90% 所需時間：

| | 中位數 | p90 | max |
|---|---|---|---|
| 衰減時間 | 1.80s | 2.86s | 3.65s |

逐姿勢：`shoulder_flex` 2.38s、`pick_and_raise` 2.70s（最慢）；`index_flex` 0.65s、`thumb_flex` 0.72s（最快）。

舊設定 `return 1.5 + margin 0.5 = 2.0s` 只覆蓋約一半 → **rest 標籤（最大的類別）被高活動訊號汙染**，
`shoulder_flex` 的 release 前 0.5s 是基線的 **8.07×**。

**關鍵觀念：`CUE_RETURN_SEC + CUE_MARGIN_REST_START_SEC` 才是真正的衰減預算。**

| 預算 | 覆蓋率 |
|---|---|
| 3.0s | 90% |
| **3.5s（採用：return 2.5 + margin 1.0）** | **98%** |
| 4.0s | 100% |

取 3.5s 而非 4.0s：最後 2% 的尾巴交給 `audit_trials.py` 逐 trial 標記。
**協定覆蓋典型情況，稽核抓尾巴。**

> 這也解釋了先前記錄的「offset 偵測慢 1.75s」—— 與衰減中位數 1.80s 吻合。
> 那不只是生理現象，**有一部分是標籤汙染教出來的**。

### 5.3 逐 trial 稽核的討論

使用者問「錄的時候無法全程專注、來不及記下哪次做錯，怎麼挑出來？dropout 能解決嗎？」

**dropout 解決不了** —— 它是防特徵共適應的正則化，不是防標籤雜訊。
每個姿勢只有 5 次，錯 1 次 = 該姿勢 20% 的資料錯，是**系統性**偏差。

第一份錄音的稽核結果（40 trial 標記 5 個，12%）：

| rep | cue | 稽核判定 |
|---|---|---|
| 0 | index_flex | 手部做錯（要 index → 判 pinch，3%） |
| 5 | arm_lift | 手部做錯（要 rest → 判 pinch，0%） |
| 19 | elbow_flex | rest 沒放鬆（需 3.6s > 預算 3.5s） |
| 20 | shoulder_flex | 手肘做錯（要 rest → 判 flex，3%） |
| 35 | elbow_flex | 肩膀做錯（要 rest → 判 flex，22%） |

全部是「多做了一個部位」，錯誤模式解剖上可解釋。

**逐 DOF 比整體姿勢比對可靠**：整體法在 trial 3、21 給了誤報，逐 DOF 顯示那兩個三部位全部相符。
**否定對照已驗**：人工把 rep 27 從 `elbow_flex` 改標成 `shoulder_flex`，工具準確報出兩個 DOF 都 0%。

**為什麼整個 trial 刪除，而不是只遮蔽出錯的 DOF**（使用者的理由，成立）：
**通道之間是耦合的**。多做的 pinch 會透過 crosstalk 汙染其他通道，
而且 120 維特徵裡有 15 個是**跨通道比值**。只遮蔽 hand 的標籤等於拿**被汙染的特徵**去配「正確」的標籤。

### 5.4 ★ 第一組真實數字

在此之前**所有數字都來自合成資料**。排除 5 個 trial 後（1,962 視窗、36 trial）：

| 評估 | 全對率 |
|---|---|
| 基準線（全猜 rest） | 33.8% |
| **trial 分組 5 折（主要指標）** | **88.4% ± 11.1%** |
| within-session（前 70%／後 30%） | 95.1% |

逐自由度：**肩膀 99–100% 最穩、手肘 84–100%、手部 78–100% 最弱** ——
合理，手部要分 4 個協同模式而且 3 顆電極高度重疊。

三組對照（同一份錄音、同一種切分）：

| 設定 | trial 5 折 | within-session | 參數 |
|---|---|---|---|
| **tiny + 排除 5 個** | **88.4% ± 11.1%** | 95.1% | 11,625 |
| zhao + 排除 5 個 | 86.1% ± 8.5% | 94.3% | 355,784 |
| tiny + 不排除 | 86.1% ± 9.8% | 89.6% | 11,625 |

**⚠️ 這三組分不出來。** 差異都是 ~2pp，而折間標準差是 ±8–11pp ——
1 位受試者、5 折，統計上無法區辨。**不要拿這個宣稱 tiny 比 zhao 好，也不要宣稱排除 trial 有效。**

**目前唯一站得住的三件事**：
1. **88.4% vs 基準線 33.8%** —— 模型確實學到東西，不是猜 rest
2. **逐 DOF 的順序穩定**：肩膀 ≥ 手肘 > 手部，在四種設定下都一樣 —— 這是真的模式，不是雜訊
3. **tiny 用 1/30 的參數達到同樣準確率** —— 對部署而言結論明確（延遲抖動更小、過擬合風險更低）

⚠️ 只有 1 位受試者 1 次錄音，**沒有 LOSO、沒有跨 session**。這是起點不是結論。

## 6. 方法論教訓（最重要的一節）

### 6.1 ★ 否定對照：四個錯誤全都讓分數變高

寫 `check_states.py` 時，用「訊號上完全沒有資訊」的合成資料當否定對照
（正確答案必須是 50%），連續抓出**四個**方法錯誤：

| # | 錯誤 | 錯誤結果 | 修法 |
|---|---|---|---|
| 1 | 隨機切窗 | 89.4% | 按 trial 分組切分 |
| 2 | 段落固定循環（濾波器記憶洩漏「前一段是什麼」） | 66.1% | 打散順序 + 邊界內縮 |
| 3 | 其他自由度沒隔離（`index=rest` 混進 `thumb_flex` 的視窗） | 89.1% | 只用其他 DOF 都 rest 的視窗 |
| 4 | 用原始正確率（多數類基準 86.8%） | 87.9% | **balanced accuracy** |

錯誤 3 特別隱蔽：分類器能靠「拇指安不安靜」作答 —— 差最大的特徵全是 `thumb_*`，跟食指毫無關係。

修完之後：無資訊 → **51.2%**，有訊號 → 100%。

> **這四個錯誤沒有一個會在正向案例中暴露 —— 它們全都讓分數變高。**
> 所以任何「能不能分開」的檢查，都必須先跑一個**答案已知為「不能」**的否定對照。

### 6.2 其他通則

| 教訓 | 出處 |
|---|---|
| **穩健性不能替代一致性**：訓練與推論的每一個統計量都必須問「線上拿得到嗎？定義一樣嗎？」 | 尺度來源 1.27× bug |
| **異常整齊的數字優先懷疑 bug**（0.0%、100.0%） | within-subject 三人都 0.0% |
| **延遲要拆解量測，不要從架構推論** | 延遲歸因錯誤 |
| **長時間任務的最後一步要先用小樣本測過** | savez 跑 363 秒才爆 |
| **黑名單式過濾遲早會漏**，改用正面判準 | `discover()` 誤收 `_audit.csv` |
| **寫死的說明文字在調參後會變成錯的** | `POSE_SPEC` 兩次寫死秒數 |
| **圖例與資料來源必須是同一個變數** | 繪圖用錯欄位 |
| **合成資料只能證明「兩個分支都會動」**，不能定門檻、不能比架構 | 串音門檻、SEQ_LEN 消融 |
| **狀態數由訊號決定，語意由控制層決定** | 手指 ext 態的來回 |
| **協定要吸收變異，不要假設變異不存在** | 反應時間 → 加長 action 而非回收 prepare |
| **協定覆蓋典型情況，稽核抓尾巴** | 衰減預算取 3.5s 而非 4.0s |
| **「懷疑但查核後不成立」也該留紀錄** | `PER_CH_NAMES` 誤報 |

## 7. V1 → V2 對照速查

| 面向 | V1（SoftPINCH） | V2（現行） |
|---|---|---|
| **通道** | 3（曲腕肌 / 食指 / 拇指） | **7**（+ 背闊肌 / 三角肌前束 / 三頭肌 / 二頭肌） |
| **進模型的東西** | 40 Hz RMS 包絡線 | **120 維多域特徵**（從濾波後原始波形） |
| **視窗** | 3.0s | **0.5s / 步進 50ms** |
| **正規化** | z-score（mu/sigma 絕對 mV） | **MAD 穩健尺度 + 尺度不變特徵** |
| **標籤來源** | 猜 trial 邊界 → 固定切三等分 | **cue 檔的 sample_index** |
| **相位** | 位置式（離線）／斜率式（realtime），兩者不同任務 | preview/prepare/return 丟棄；go = 姿勢；release = rest |
| **輸出** | 5 類互斥（無 pinch） | **3 個 DOF 頭 (4,2,2)**，16 種組合 |
| **模型** | Conv1D + 單向 LSTM 取最後步 | **深度可分離時間 CNN + Attention pooling + 多頭** |
| **參數** | 42,245（離線）／344,583（realtime） | **11,625** |
| **延遲** | ~3.3s | **1.15s** |
| **交叉驗證分組** | 隨機切窗（洩漏） | **trial 分組**（序列堆疊另用 segment 鍵） |
| **報告的數字** | 一個 | **四個** scheme + balanced accuracy + exact match + 基準線 |
| **錄製協定** | 單一手勢固定循環，無時間戳 | **一檔多姿勢 + cue + metadata + 逐 trial 稽核** |
| **錄製起點** | 不確定（開窗延遲 + UART 舊資料） | **t0 = 第一個被接受的樣本** |
| **頭尾** | 事後硬切 2s/1s | 錄製時保留 5s/5s 空白 |
| **參數管理** | 散落各檔 | `config.py` 集中，且有 `validate()` |

## 8. 仍未解決的事
