# 2. 實驗協定與資料集

## 2.1 協定設計

每個 trial 的時間結構（V3 協定，`protocol_version = 2`）：

```
▶▶ preview   1.5 s   螢幕預告下一個姿勢，受試者仍在休息、只用眼睛讀
   prepare   2.0 s   移動到目標姿勢          ← 不列入訓練
   go        4.0 s   ★ 維持不動              ← 這段才是訓練資料
   return    2.5 s   回到中性                ← 不列入訓練
   rest      5.0 s   在中性完全放鬆          ← 標成 rest
                     ─────────────
                     15.0 s / trial
```

8 個動作 × 5 次重複 = 40 trials × 15 s + 前後各 5 s = **550 s（9 分 10 秒）**

### 為什麼要有 preview（1.5 s）

如果 cue 出現的當下就要求受試者做動作，`go` 段的開頭會被**反應時間**汙染。
實測 gary 的反應時間中位 0.40 s、最大 1.00 s，而且**因人、因疲勞、因姿勢複雜度而異**
（複合姿勢 `arm_lift` 0.52 s vs 單一姿勢 `index_flex` 0.22 s）。

⚠️ **不能假設「cue 時間戳當下受試者已經在做該姿勢」** —— 這是 V1 的錯誤之一。

### 為什麼標籤還要再往內縮 margin

即使有 prepare 段，`go` 的頭尾仍不乾淨。三個 margin **數值不同，因為吸收的東西不同**：

| margin | 值 | 吸收什麼 |
|---|---|---|
| `go` 起始 | 0.5 s | 受試者還在微調姿勢，變異大 |
| `rest` 起始 | **1.0 s** | ★ 肌肉還在**放鬆** —— 這是生理衰減，比擺姿勢慢得多 |
| 結束 | 0.2 s | 提前放鬆，通常很短 |

`rest` 起始特別長的依據：實測從 `return` 起點衰減 90% 需要 p90 **2.86 s**、
max **3.65 s**。協定的衰減預算是 `return(2.5) + rest起始margin(1.0) = 3.5 s`，覆蓋 98%。

### 姿勢必須**懸空**

metadata 裡明確寫入的規範：

> 維持姿勢時手臂必須**懸空** —— 手肘靠桌面、前臂撐在扶手、或上臂貼死在身側，
> 都會讓重力被外物支撐掉，肌肉不需出力、EMG 消失，系統會判成 rest。

這不是小事：等長收縮下 EMG 振幅正比於肌肉張力，一旦重力被外物承擔，
訊號會直接消失，訓練資料就會出現「標成 flex 但看起來像 rest」的樣本。

## 2.2 為什麼是 9 種組合，不是 16 種

三個自由度理論上有 $4 \times 2 \times 2 = 16$ 種組合。實際 cue 的只有 9 種：

| 動作名 | hand | elbow | shoulder | 說明 |
|---|---|---|---|---|
| （rest） | rest | rest | rest | 每個 trial 之間都有 |
| `index_flex` | index | rest | rest | |
| `thumb_flex` | thumb | rest | rest | |
| `pinch` | pinch | rest | rest | |
| `elbow_flex` | rest | flex | rest | |
| `shoulder_flex` | rest | rest | flex | |
| `arm_lift` | rest | flex | flex | 肩前舉 + 肘彎曲 |
| `pick_and_lift` | pinch | flex | rest | 捏住 + 抬起 |
| `pick_and_raise` | pinch | flex | flex | 三個一起 |

**沒有 cue 到的 7 種組合**，例如 `index + elbow_flex`、`thumb + shoulder_flex`。

### 為什麼不錄滿 16 種

錄滿要 16 個動作 × 5 次 × 15 s ≈ **17 分鐘**。實務上：

- 受試者專注度會掉 → 人為錯誤率上升（第一份錄音 40 個 trial 就有 4 個做錯）
- 肌肉疲勞 → 後半段的 EMG 振幅與前半段不可比

**這正是選擇多輸出架構的理由**：三個頭各自預測，理論上應該能組合出
沒 cue 過的姿態，不需要窮舉。

⚠️ **但實測發現這件事並不自動成立** —— 這是本專案最重要的技術發現，
詳見 `05_模型架構與選型論證.md` §3。

## 2.4 資料品質管理的三種標記

| 檔案 | 意義 | 處理方式 |
|---|---|---|
| `_badspans.txt` | **訊號**壞掉的時間段（突波、飽和） | 遮蔽該段的**標籤**，重疊 >5% 的視窗丟棄 |
| `_exclude.txt` | **執行**錯誤（受試者做錯、錄音中斷） | 排除指定的 trial |
| `_EXCLUDE.txt` | 整份不用 | 整份排除 |

⚠️ 遮蔽的是**標籤不是樣本** —— 樣本仍要留著，因為串流濾波器有狀態，
把樣本抽掉會讓濾波器狀態與實際部署不一致。

實際套用情形：

```
multi_gary_20260811_17-11-49    1 段、共 20 s
multi_gary_20260811_17-23-12    1 段、共  9 s
multi_neil_20260810_21-17-16    1 段、共 89 s
multi_neil_20260810_21-35-03    排除 2 個 trial（錄音中斷）
```

## 2.5 ★ 本次新增：錄音前的品質檢查

新工具 `V5moving/run_qc.py`：一張圖看完 7 通道 + cue 對照，逐通道判定 OK / ⚠ / ✗。

判定依據六項指標：

| 指標 | 定義 | 抓什麼 |
|---|---|---|
| `clip` | $\lvert \mathrm{counts}\rvert \ge 0.98 \times 2^{23}$ 的比例 | ADC 撞滿刻度 |
| `flat` | 連續 ≥25 ms 數值完全不變的比例 | 線斷、ADC 卡住 |
| `noise` | RMS 包絡線的 p10（基線） | 底噪過高 |
| `dyn` | p95 / p10 | 有沒有調變（整份平坦 = 沒接到肌肉） |
| **`f60`** | 60±2 Hz 功率佔 20–450 Hz 的比例（**陷波前**） | ★ 電極接觸阻抗 |
| `art` | 突波段落佔全長比例 | 動作假影、拉到導線 |

**建議流程**：貼好電極 → 錄 30 秒 → `run_qc.py` → 七個通道都 OK → 再開始錄那 9 分鐘。
否則錄完 9 分鐘才發現不能用。
